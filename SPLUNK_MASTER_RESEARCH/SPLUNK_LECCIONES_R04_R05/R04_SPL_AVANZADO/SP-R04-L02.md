# SP-R04-L02 — Secuencias con streamstats

**Región:** SP-R04 · **Prioridad:** P0/P1 SOC · **Estado:** borrador educativo para revisión · **SPL real:** no ejecutado.  
**ID curricular intacto:** `SP-R04-L02` · **Resultado de aprendizaje:** Calcular acumulados y secuencias controlando orden temporal  
**Prerrequisitos:** R03 completada · **Producto:** Splunk Enterprise/Cloud con SPL clásico según versión y permisos; CIM exige configuración pertinente.

## 1. Pregunta esencial

Un SOC puede necesitar la cantidad de intentos acumulada **hasta ese evento**, no el total final. `streamstats` calcula estadísticas en el orden en que llegan las filas al comando. La búsqueda estándar suele mostrar eventos recientes primero; para un acumulado cronológico debes ordenar explícitamente. Sin ese paso, el resultado puede responder otra pregunta temporal.

**Objetivo verificable:** Calcular acumulados y secuencias controlando orden temporal.

## 2. Modelo mental y conceptos

1. `sort 0 _time` ordena por tiempo ascendente sin truncar explícitamente las filas a la cantidad implícita del comando sort; ordenar grandes volúmenes puede ser costoso.
2. `streamstats count AS secuencia BY src` produce un contador acumulado por IP, reiniciado para cada valor de src.
3. Una búsqueda con `streamstats` no calcula automáticamente una ventana móvil; `window` y `time_window` tienen semánticas propias que deben justificarse.
4. Cuando hay timestamps iguales, define un segundo criterio determinista; de otro modo los resultados pueden variar con el orden de llegada.

## 3. Procedimiento guiado

1. Filtra `action=failure` en los eventos sintéticos y ordena por `_time` ascendente.
2. Calcula el contador global y luego `BY src`; observa por qué el segundo separa las dos IP.
3. Cambia el orden a descendente y explica por qué las cifras ya no corresponden al acumulado cronológico.
4. Para ventanas móviles, discute cuándo tiene sentido `time_window=15m` y cuándo conviene `bin` para ventanas discretas no deslizantes.

## 4. SPL ilustrativo — no ejecutado

```spl
index=INDICE_AUTH sourcetype=SOURCETYPE_AUTH action=failure earliest="10/16/2026:09:00:00" latest="10/16/2026:09:15:00"
| sort 0 _time event_id
| streamstats count AS fallos_acumulados BY src
| table _time src user fallos_acumulados
```

**Interpretación, condiciones y alcance:** El ejemplo acota el primer bucket en UTC: .9 termina en siete y la otra IP tiene su propio contador. Sobre todo el CSV, .9 termina en nueve. event_id desempata timestamps; exige que esté disponible y sea estable. sort 0 es didáctico y puede ser costoso. No es una ventana móvil ni una búsqueda ejecutada en Splunk.

**Nota de seguridad:** `INDICE_*`, `SOURCETYPE_*` y nombres de lookups son marcadores pedagógicos. No están instalados ni descubiertos en tu laboratorio. Los SPL de este bloque son búsquedas de lectura, no indicaciones para modificar índices, apps, permisos o configuraciones.

## 8. Solucionario razonado

**Q01 → B.** Conteo acumulado hasta cada fila. El cálculo se emite progresivamente en el orden del pipeline.

**Q02 → B.** Garantizar orden y semántica de `_time`. Sin orden temporal, el acumulado no responde a la hipótesis cronológica.
