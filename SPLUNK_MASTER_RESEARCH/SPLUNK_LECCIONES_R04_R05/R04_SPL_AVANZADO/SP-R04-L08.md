# SP-R04-L08 — Proyecto: investigación cruzada SPL

**Región:** SP-R04 · **Prioridad:** P0/P1 SOC · **Estado:** borrador educativo para revisión · **SPL real:** no ejecutado.  
**ID curricular intacto:** `SP-R04-L08` · **Resultado de aprendizaje:** Crear una línea de tiempo y separar hipótesis de evidencia  
**Prerrequisitos:** R03 completada · **Producto:** Splunk Enterprise/Cloud con SPL clásico según versión y permisos; CIM exige configuración pertinente.

## 1. Pregunta esencial

El proyecto integrador combina todo el bloque: define una hipótesis de spraying, construye una agregación temporal, pivota a eventos relevantes y documenta qué evidencia queda fuera. Un buen entregable distingue lo observado en la fixture, lo que sugiere y lo que no demuestra. Si no existen eventos posteriores de éxito, esa ausencia puede deberse a falta de cobertura.

**Objetivo verificable:** Crear una línea de tiempo y separar hipótesis de evidencia.

## 2. Modelo mental y conceptos

1. Hipótesis: desde una IP se intentan varias cuentas en poco tiempo. Evidencia: fallos, identidades distintas y serie temporal.
2. Controles: filtrar correctamente origen y ventana, comprobar nulos, distinguir IP compartida y cuentas de servicio.
3. Una búsqueda orientada a detección requiere umbral defendible y datos comparables. Aquí se usa un fixture generado para enseñar, no un baseline real.
4. Informe SOC: consulta, período, fuente, números verificables, contexto, hipótesis alternativa, limitaciones y siguiente paso autorizado.

## 3. Procedimiento guiado

1. Ejecuta el verificador offline para conocer los números canónicos sin Splunk.
2. Propón búsqueda que agrupe fallos por src y bloque de 15m; documenta que el resultado de 09:00 cumple >=5 cuentas.
3. Correlaciona éxito de alice a las 09:11 sin afirmar que resulte del patrón previo.
4. Entrega cronología, informe y una decisión INCONCLUSO o INVESTIGAR, con justificación.

## 4. SPL ilustrativo — no ejecutado

```spl
index=INDICE_AUTH sourcetype=SOURCETYPE_AUTH action=failure earliest=-24h
| bin _time span=15m
| stats count AS fallos dc(user) AS cuentas BY src _time
| where cuentas>=5
```

**Interpretación, condiciones y alcance:** En esta fixture el bucket 09:00 de 203.0.113.9 tiene 7 fallos y cinco identidades; el posterior éxito alice requiere análisis adicional. Las búsquedas no se han ejecutado en Splunk: son propuestas contra un esquema declarado.

**Nota de seguridad:** `INDICE_*`, `SOURCETYPE_*` y nombres de lookups son marcadores pedagógicos. No están instalados ni descubiertos en tu laboratorio. Los SPL de este bloque son búsquedas de lectura, no indicaciones para modificar índices, apps, permisos o configuraciones.
