# SP-R04-L01 — Agregaciones con stats frente a eventstats

**Región:** SP-R04 · **Prioridad:** P0/P1 SOC · **Estado:** borrador educativo para revisión · **SPL real:** no ejecutado.  
**ID curricular intacto:** `SP-R04-L01` · **Resultado de aprendizaje:** Elegir la agregación adecuada preservando o no eventos originales  
**Prerrequisitos:** R03 completada · **Producto:** Splunk Enterprise/Cloud con SPL clásico según versión y permisos; CIM exige configuración pertinente.

## 1. Pregunta esencial

En un turno SOC necesitas saber cuántas autenticaciones fallidas acumula una IP, pero también conservar cada evento para pivotar. `stats` resume el flujo en una tabla: desaparecen los eventos individuales de esa salida. `eventstats` calcula el total del grupo y lo adjunta a cada fila sin colapsarla. `streamstats`, que estudiarás después, calcula acumulados dependientes del orden. Confundirlos cambia la evidencia que puedes conservar.

**Objetivo verificable:** Elegir la agregación adecuada preservando o no eventos originales.

## 2. Modelo mental y conceptos

1. `stats count AS fallos dc(user) AS usuarios BY src` devuelve una fila por src; `dc` cuenta valores distintos presentes, no representa nulos como identidades nuevas.
2. `eventstats count AS fallos_por_ip BY src` añade el total global del grupo a las filas originales que siguen en el pipeline.
3. Filtrar `action=failure` antes de agregar cambia el universo de eventos; filtrar después de `stats` ya no puede recuperar la clase de eventos eliminada.
4. `stats` permite muchas medidas, pero los campos no incluidos en agregaciones ni BY no estarán disponibles para pivotar desde esa tabla.

## 3. Procedimiento guiado

1. Toma `auth_events.csv` y selecciona solamente los eventos cuyo action sea `failure`.
2. Agrupa por src. Para 203.0.113.9, la fixture tiene siete fallos hacia cinco identidades no vacías en el bucket 09:00.
3. Repite con eventstats: las siete filas de fallos siguen presentes y cada una recibe total=7. Comprueba por qué una lista de eventos para triage resulta distinta de una tabla resumida.
4. Documenta que la IP compartida y la ausencia de eventos de éxito/fracaso en otras fuentes impiden afirmar compromiso.

## 4. SPL ilustrativo — no ejecutado

```spl
index=INDICE_AUTH sourcetype=SOURCETYPE_AUTH src="203.0.113.9" action=failure earliest="10/16/2026:09:00:00" latest="10/16/2026:09:15:00"
| stats count AS fallos dc(user) AS cuentas BY src
```

**Comparación con otro patrón sobre el mismo objetivo:**

```spl
index=INDICE_AUTH sourcetype=SOURCETYPE_AUTH src="203.0.113.9" action=failure earliest="10/16/2026:09:00:00" latest="10/16/2026:09:15:00"
| eventstats count AS fallos_por_ip BY src
| table _time src user action fallos_por_ip
```

**Interpretación, condiciones y alcance:** Usuario/search head en UTC y _time mapeado correctamente: el rango [09:00,09:15) del 16/10/2026 y src seleccionan siete fallos de .9. Sin restringir al primer bucket, el CSV completo contiene nueve fallos de esa IP. Índice/sourcetype siguen siendo marcadores no ejecutados; no se autoriza importar datos.

**Nota de seguridad:** `INDICE_*`, `SOURCETYPE_*` y nombres de lookups son marcadores pedagógicos. No están instalados ni descubiertos en tu laboratorio. Los SPL de este bloque son búsquedas de lectura, no indicaciones para modificar índices, apps, permisos o configuraciones.

## 5. Caso SOC

Una regla muestra siete fallos desde una IP y cinco identidades distintas en un cuarto de hora. El analista debe exponer las siete evidencias, no solo el conteo.

## 7. Solucionario con razonamiento

- **SP-R04-L01-Q01: A** — eventstats adjunta una métrica a filas originales. stats las transforma en filas agregadas.

- **SP-R04-L01-Q02: D** — El número de eventos y la cardinalidad de un campo pueden divergir por valores ausentes.

- **SP-R04-L01-P01:** `stats count dc(user) BY src` resume; `eventstats count BY src` preserva filas. Con el filtro de fallos y la fixture: 203.0.113.9 tiene 9 fallos totales en todo el dataset (7 de 09:00 a 09:14 y 2 de 09:15 a 09:29); para 09:00 específicamente 7 fallos / 5 usuarios. Sin filtro, se incluyen éxitos en los totales.
