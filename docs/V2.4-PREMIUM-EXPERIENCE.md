# V2.4 · Premium Experience

Versión 0.2.4, sobre V2.3 validada. Se conserva la aplicación React/TypeScript existente, el layout panorámico V2.2 y el motor educativo. V2.5 queda fuera de esta ejecución.

## Implementado

### Orientación y navegación

- Selector de regiones y leyenda visibles durante el desplazamiento, con anterior/siguiente, capítulo seleccionado y disponibilidad calculada por el motor existente. La opción de una región bloqueada sigue siendo una vista previa, nunca un desbloqueo.
- «Tu posición» vuelve al nodo real del atlas y funciona también al repetir la acción sobre la misma URL. Las cuatro marcas principales (candado/play/check/estrella y texto) no dependen solo del color; En curso se conserva como estado existente.
- `rememberMapPosition` añade el parámetro `nodo` ya soportado a la entrada actual del historial al abrir un nodo. Atrás del navegador y gestos de retorno recuperan foco y contexto, igual que los enlaces explícitos. Ctrl/Cmd/Shift-clic conservan la navegación normal. No se añade almacenamiento ni progreso paralelo.
- En el lector, el retorno al mapa permanece accesible durante scroll. Índices/fases tienen espacio bajo ese control. El foco de un paso o feedback se desplaza solo cuando queda fuera del área útil; el foco de la respuesta no lo roba el encabezado del lector. Se contempla la carga diferida de la lección.
- Requisitos de nodos bloqueados: foco en la explicación, Escape o Entendido para cerrar y devolución del foco al control de origen. Se conserva como aviso no modal.
- Caminos con acabado diferenciado para tramos bloqueados, disponibles y completados; el tramo al cofre usa el estado real del capítulo. El lector original y el educativo comparten un acento discreto del bioma, sin ilustraciones detrás de la lectura.

### Movimiento y feedback

La skill `animate` se aplica con dos propósitos: feedback frecuente muy breve y continuidad espacial al navegar. Las recompensas reales usan una entrada ocasional; no se anima el paisaje ni se retrasa la navegación.

| Interacción | Implementación | Tiempo |
| --- | --- | --- |
| Pulsación/liberación | CSS, transform, curva `--ease-out` | 120 ms |
| Región / cambio de región | Bienvenida, opacity + 6 px, WAAPI | 200 ms |
| Abrir lectura | Superficie cuando termina de cargar, opacity + 6 px | 200 ms |
| Regresar al nodo | Placa del nodo, opacity + escala .97→1 | 200 ms |
| Responder / completar | Feedback visible y enfocado, opacity + 4 px | 150 ms |
| Evaluación aprobada | Medallón existente, opacity + escala .95→1 | 200 ms |
| Nuevo estado disponible/completado/dominado | Plataforma del nodo, opacity + escala .94→1 | 200 ms |
| XP/nivel | Avatar tras cambio real de estadísticas, escala breve | 150/200 ms |
| Cofre conseguido | Confirmación al pasar a completo, opacity + transform | 200 ms |

`presentation.ts` reutiliza los tokens de V2.1. Las animaciones imperativas se cancelan al navegar, usar el teclado o activar movimiento reducido; limpian sus listeners. El teclado no tiene entradas animadas. Movimiento reducido elimina desplazamientos de pulsación y de navegación, incluidas reglas con especificidad suficiente para sobreponerse a `:not(:disabled):active`. Hover permanece limitado a puntero preciso.

Las animaciones nunca llaman a `send`, `applyLearning` ni a una función de recompensa. `Header` observa las estadísticas existentes: informa del delta real de XP, nivel, dominio y capítulo, mediante una región live discreta y el avatar. `AdventureMap` solo compara su última representación en memoria para confirmar transiciones reales. No anima otra vez cofres conseguidos al volver a visitarlos. El último capítulo no promete una región siguiente inexistente.

## Validado

Los resultados definitivos, cifras y capturas están en `output/playwright/v24-premium-world/ENTREGA.md` e `index.html`.

- V2.3 pasó su validación antes de comenzar V2.4; conserva capturas, informes y un ZIP de su build.
- 38 pruebas unitarias; TypeScript y build de producción correctos. Se añaden dos regresiones del catálogo visual/geometría, conservando todas las pruebas previas.
- Mundo: 84 escenarios de atlas/13 regiones en seis anchuras. Layout: 98 controles, incluidos 320 px, bordes de breakpoint, resize, cruces y movimiento reducido.
- UX: 13 grupos, con 13 destinos del selector a 390/1440/2560 px, historial Atrás/Adelante, retorno/foco, pulsación/liberación, aviso/Escape y movimiento reducido. Una actividad real conserva su explicación y foco; otro recorrido real completa un capítulo y sincroniza atlas/cofre/XP entre pestañas de un contexto aislado. 200→310 XP y nivel 2 corresponden a ese fixture, no al perfil personal.
- Regresión educativa: 11 grupos, 76 originales/guías y 35 actividades con aciertos/errores; 80%, XP acotados, dominio, desbloqueo, migración V1, recarga, exportación y guardados corruptos/no disponibles.
- Regresión visual: 10 grupos; los 75 nodos de lectura de los trece capítulos se abren y devuelven foco/contexto.
- Axe-core 4.10.3: 0 violaciones automáticas en 60 vistas a 390/768/1440 px, incluidas las trece regiones. Se comprueban también interacciones reales de foco, teclado, Escape y área tocable. No equivale a certificación ni reemplaza lector de pantalla o contraste manual sobre gradientes.
- Rendimiento: V2.2 frente a V2.3 y frente a V2.4, con tres muestras alternadas por vista/anchura, CPU 4× en móvil y sin otras suites de navegador simultáneas. No se afirman FPS ni resultados de teléfono físico.

## Integridad y límites

Se conservan SC-200.md, todos los generadores/payloads/catálogos, IDs y revisiones, motores de corrección/progreso/guardado, 13 capítulos, 76 lecturas, 719 pasos, 35 actividades y 67 lecturas pendientes. Sin cambios en el 80%, XP/niveles/recompensas, esquema/claves LocalStorage, compatibilidad, exportación o Splunk. Las diferencias de `LearningReader`, `QuestionCard` y `Reader` son foco, presentación, acento y mensajes de estado; preguntas/respuestas/explicaciones proceden de los mismos payloads intactos.

No se instalan dependencias ni se usan backend, autenticación, bases de datos, WebGL, motores 3D, vídeo de fondo o animaciones ambientales. No se hacen commits ni publicaciones.

Pendientes externos a las validaciones ejecutadas: lector de pantalla manual, Safari/Firefox, teléfono físico y contraste manual sobre fondos/gradientes. No se enriquecen las 67 lecturas ni se integra Splunk. La inspección de rendimiento conserva sus límites de laboratorio local y no demuestra 60 FPS.

## Ejecutar y comprobar

Usar la instancia existente en `http://127.0.0.1:5173/` con el mismo navegador/perfil. Si no existe, desde el proyecto:

```sh
npm run dev
# Alternativa con el build local:
python3 -m http.server 5173 --bind 127.0.0.1 --directory dist
```

No iniciar otro servidor en un origen distinto para recuperar el progreso, y no abrir mediante file://. Para pruebas futuras tras cambios, con contextos aislados:

```sh
npm run verify
node tests/e2e.mjs --base-url http://127.0.0.1:5173/
node tests/e2e.mjs --world --base-url http://127.0.0.1:5173/
node tests/e2e.mjs --experience --base-url http://127.0.0.1:5173/
node tests/e2e.mjs --full-width --base-url http://127.0.0.1:5173/
node tests/e2e.mjs --visual --base-url http://127.0.0.1:5173/
```

Las suites aceptan `--output-dir output/playwright/...`. Axe requiere `--a11y --all-regions --axe-path /ruta/axe.min.js`. No repetir suites ya aprobadas sin cambios o incidencia. La revisión se guía por las [Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md).
