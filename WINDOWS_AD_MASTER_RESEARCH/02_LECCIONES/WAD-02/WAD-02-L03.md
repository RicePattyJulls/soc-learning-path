## 1. Objetivo

Leer el estado de configuración con herramientas de solo lectura y describir cómo revertir un cambio controlado con evidencia.

Prerrequisitos: `WAD-02-L02` (servicios, tareas y dependencias).

## 2. Comprende el mecanismo

El **Registro** de Windows es una base jerárquica de **claves y valores** donde el sistema y las aplicaciones guardan configuración: servicios, controladores, políticas, asociaciones de archivos y también puntos de arranque automático. No es «la carpeta del malware»: es configuración, y precisamente por eso es útil para entender un sistema y para auditar **persistencia**.

**WMI/CIM** ofrece un modelo para consultar el sistema (procesos, servicios, discos, sistema operativo) mediante clases en espacios de nombres como `root\cimv2`. Es cómodo para inventario porque devuelve objetos comparables. Aquí conviene una distinción tajante:

- **Consultar** (leer) no cambia el sistema.
- **Invocar métodos** que cambian estado (crear, detener, modificar) sí lo cambia, exige autorización y un plan de reversión.

Un cambio **reversible** no es improvisar: es un procedimiento con estado inicial y final definidos.

1. **Estado inicial**: anota la configuración actual (valor, clave, ruta) y guarda una copia del objeto afectado.
2. **Reversión definida**: decide de antemano cómo volver atrás (restaurar el valor guardado o recuperar una instantánea de la máquina virtual).
3. **Cambio controlado**: aplícalo en un laboratorio aislado y con el alcance mínimo.
4. **Verificación**: comprueba el efecto observado, distinguiéndolo de lo que solo **infieres**.
5. **Reversión y re-verificación**: revierte y confirma que el sistema quedó como al principio.

Dos cautelas. Primero, el registro puede contener **material sensible** (credenciales, claves), así que no se exportan ramas completas ni se publican. Segundo, parte del registro está protegida o exige privilegios elevados: «no verlo» no significa «no existir».

### Vocabulario de apoyo

- **Registro**: base jerárquica de configuración del sistema y de las aplicaciones.
- **Clave / valor**: unidad de organización del registro y dato almacenado en ella.
- **Hive**: archivo que respalda una rama del registro.
- **WMI/CIM**: modelo para consultar —y, con métodos, modificar— objetos del sistema.
- **Espacio de nombres**: ruta de clases WMI, por ejemplo `root\cimv2`.
- **Reversión (rollback)**: volver al estado previo a un cambio.

## 3. Caso resuelto

**Datos sintéticos para análisis; no son una captura ni una ejecución real.**

> Caso sintético: para habilitar una función de diagnóstico, un compañero propone cambiar un valor del registro en un host de producción y pide «hacerlo rápido, total es una clave pequeña».

El tamaño de la clave no mide el riesgo. Antes de tocar nada: se lee y se anota el valor actual (y se guarda la clave), se define la reversión (restaurar el valor o revertir una instantánea), se aplica primero en una **máquina virtual con instantánea**, se verifica el efecto observado y, por último, se revierte y se confirma el estado inicial. En producción, si el cambio no es imprescindible y no hay ventana ni autorización, la respuesta correcta es **no aplicarlo todavía** y dejar documentado el plan.

## 6. Aplicación profesional

- SOC: Leer configuración y puntos de arranque sin alterarlos, para correlacionarlos después con los eventos.
- Red Team autorizado: Documentar puntos de persistencia como hipótesis en laboratorio; no modificar sistemas fuera del alcance acordado.
- Evidencia de la etapa: Estado de configuración guardado + árbol proceso-servicio + prueba de reversión.
- Criterio de dominio: Consulta sin modificar y demuestra la reversión de un cambio controlado con evidencia.
