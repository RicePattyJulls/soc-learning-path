## 1. Objetivo

Obtener un inventario de host reproducible que distinga datos observados de inferencias.

Prerrequisitos: `WAD-01-L02` (UEFI, BCD y servicios base).

## 2. Comprende el mecanismo

Un **inventario reproducible** es el mismo conjunto de datos obtenido con el mismo método, en un formato que otra persona puede volver a leer y comparar. No basta con mirar la pantalla: hay que registrar **qué** se consultó, **con qué** comando o herramienta, **cuándo** (en UTC) y sobre **qué host** (nombre y compilación exacta).

Datos mínimos de un host Windows:

- **Producto, compilación exacta y edición.** La compilación se descompone en `CurrentBuild` y `UBR` (revisión), y suele acompañarse de `DisplayVersion`. `ver`, `systeminfo`, `Get-ComputerInfo` o el registro de versión del sistema permiten leerla.
- **Parches aplicados.** `Get-Hotfix` y la lista de actualizaciones permiten fechar el estado del sistema sin abrir el Centro de actualizaciones.
- **Hardware e identidad del equipo.** `Get-CimInstance Win32_OperatingSystem`, `Win32_ComputerSystem` o `systeminfo` aportan arquitectura, memoria y modelo.
- **Red.** Direcciones, tabla de rutas y adaptadores, con la salvedad de que una IP puede ser dinámica.
- **Sesiones y software.** `qwinsta`/`quser` para sesiones, y las claves `Uninstall` del registro para software instalado con versión y ubicación.

La reproducibilidad incluye guardar la **salida** (por ejemplo, un archivo de texto con nombre de host y marca de tiempo) para poder contrastarla después. Si dos ejecuciones difieren, el valor está en la diferencia, no en memorizar un único resultado.

Una trampa frecuente: el **PID se reutiliza**. Identificar un proceso por su número sin hora, host y contexto es frágil; siempre acompaña al PID la hora y la máquina. Del mismo modo, que un dato **no** aparezca no prueba que no exista: puede no haberse consultado o no haberse registrado.

### Vocabulario de apoyo

- **Inventario**: conjunto de datos de un host obtenido con un método definido.
- **UBR**: número de revisión que acompaña a la compilación (corrección acumulada).
- **DisplayVersion**: etiqueta de la rama/versión mostrada del sistema.
- **UTC**: tiempo universal coordinado; evita ambigüedades de zona horaria.
- **CIM/WMI**: interfaz para consultar el sistema (procesos, sistema operativo, servicios).
- **Reproducible**: que otra persona obtiene y compara el mismo inventario.

[Glosario](../../05_RECURSOS/GLOSARIO.md). No necesitas memorizar todas las consultas: el objetivo es saber qué registrar y por qué.

## 3. Caso resuelto

**Datos sintéticos para análisis; no son una captura ni una ejecución real.**

> Caso sintético: dos equipos de una sala afirman tener «la misma versión» de Windows Server. Un inventario muestra que comparten `CurrentBuild` pero difieren en `UBR`.

La conclusión correcta no es «son idénticos» ni «son distintos» en abstracto: **coinciden en la compilación base y difieren en la revisión acumulada**, es decir, tienen distinto nivel de parcheo. Ese es un dato accionable. Lo que el inventario **no** demuestra por sí solo es que uno sea vulnerable: para afirmarlo haría falta una comprobación dirigida. Registrar la diferencia ya es evidencia; la interpretación de riesgo es una inferencia que hay que justificar aparte.

## 4. Práctica individual

Diseña la **cabecera** de un inventario reproducible para un host de laboratorio: enumera cuatro campos que no pueden faltar y explica por qué un quinto dato (por ejemplo, la memoria libre del momento) sería poco fiable.

Entrega una respuesta razonada: identifica los datos que utilizas, la decisión o cálculo, y el límite de tu conclusión. Resuelve antes de consultar el solucionario. Esta práctica es de análisis documental; su resolución no acredita haber ejecutado un inventario sobre un host real.

- A. Que muestre muchos datos en pantalla
- B. Que use el comando más largo posible

- A. Porque el PID cambia de formato según la edición
- B. Porque el PID se reutiliza; hace falta hora, host y contexto

- D. Porque el PID solo funciona en modo kernel

## 6. Aplicación profesional

- SOC: Registrar producto, compilación, revisión, parches y sesiones con hora UTC para contrastar dos momentos distintos.
- Red Team autorizado: Usar el inventario para situar superficie expuesta solo dentro del alcance autorizado del laboratorio.
- Evidencia de la etapa: Ficha de host + salida guardada del inventario + nota de límites.
- Criterio de dominio: Distingue datos observados de inferencias y no convierte un único resultado en una conclusión absoluta.
