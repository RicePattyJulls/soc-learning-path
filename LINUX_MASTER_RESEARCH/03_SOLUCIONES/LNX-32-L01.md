# Soluciones — LNX-32-L01

Material de revisión: consultar después de resolver.

## Práctica individual

La documentación parte del inventario y de la configuración efectiva: nombre, imagen y digest verificado, propietario, ticket y fecha. `Config.User` vacío indica que el proceso corre como root dentro del contenedor; la capability añadida amplía la superficie; seccomp sin confinar reduce el filtrado de syscalls; el montaje de escritura conecta el contenedor con datos del host; y la ausencia de límite expone al host a un consumo descontrolado. Cada dato se registra con su fuente y se compara con la línea base y el propósito declarado.

El riesgo se describe como combinación, no como una casilla aislada: usuario root interno, capability innecesaria, filtro desactivado, escritura sobre el host y recurso sin acotar. La remediación mínima propone usuario no root, retirar la capability, aplicar el perfil seccomp por defecto, reducir el montaje y fijar un límite de memoria; el retest debe comprobar que la aplicación funciona y que la configuración ya no se admite.

Límite: la inspección pasiva demuestra una exposición de configuración. No se ha ejecutado un escape ni se ha observado un efecto sobre el host, así que no se puede afirmar un compromiso.

### Criterios observables

- Reúne inventario, procedencia y configuración efectiva con propietario y fecha UTC.
- Interpreta usuario vacío, capabilities, seccomp, montajes y límites de forma relacionada.
- Distingue exposición verificada de compromiso demostrado.
- Propone remediación mínima y un retest que preserve la función legítima.

Valora precisión, relación con los datos y límites. Una respuesta alternativa puede ser válida si justifica sus supuestos y no contradice el caso. No se autocorrige como dominio práctico.

## Pregunta 1

**Respuesta: B. Que el proceso se ejecuta como root dentro del contenedor, con un riesgo que depende de capabilities, montajes y user namespace**

Un `Config.User` vacío no impide ejecutar procesos ni activa un usuario sin privilegios por sí solo. El riesgo efectivo se pondera con las capabilities, los montajes y el aislamiento del namespace de usuario.

## Pregunta 2

**Respuesta: C. Contrastar la configuración efectiva con la línea base y el propósito, con propietario, fecha y evidencia**

Una etiqueta o una ausencia de alertas no sostiene un hallazgo. La comparación documentada con el propósito y la línea base permite afirmar qué capacidad excede lo necesario y con qué alcance.
