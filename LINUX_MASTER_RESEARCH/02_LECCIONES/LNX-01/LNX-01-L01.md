## 1. Objetivo

Situar la frontera entre aplicación, shell y kernel para observar un host sin confundir capas ni privilegios.

Prerrequisitos: ninguno; puedes comenzar desde cero.

## 2. Comprende el mecanismo

Linux no es una sola pieza. Es un **kernel** que administra memoria, procesos, ficheros y red, y un conjunto de **programas** que le piden cosas mediante *llamadas al sistema* (syscalls). Cuando escribes un comando en la shell, no hablas con el kernel: hablas con un programa que, a su vez, le pide al kernel que lea un fichero, cree un proceso o envíe datos por la red.

La **shell** (por ejemplo Bash) es solo otro programa: interpreta lo que escribes, expande variables y comodines, y lanza otros programas. Por eso «ejecutar `ls`» significa *que la shell pida al sistema que arranque el programa `ls`, y ese programa pida al kernel que liste un directorio*. Son tres saltos de responsabilidad, no uno.

Cada proceso que corre lleva una **identidad**: usuario real y efectivo, grupos y capacidades. El kernel decide qué puede hacer cada proceso comparando esa identidad con los permisos del recurso. Dos comandos idénticos ejecutados por usuarios distintos pueden tener resultados opuestos; la diferencia no está en el comando, sino en quién lo ejecuta.

El kernel también expone una **vista de sí mismo**: el sistema de ficheros virtual `/proc` ofrece información de procesos y del sistema como si fuera un conjunto de archivos. Leer `/proc` es observar al kernel describir su propio estado, no ejecutar magia.

Comprender estas capas evita una confusión habitual: creer que «el sistema hizo algo» cuando en realidad lo hizo un programa con una identidad concreta. Antes de concluir nada, ubica **quién** corre, **qué** pide y **en qué capa** ocurre.

### Vocabulario de apoyo

- **Kernel**: núcleo del sistema; gestiona memoria, procesos, dispositivos y red.
- **Llamada al sistema (syscall)**: petición formal de un programa al kernel.
- **Shell**: intérprete de comandos; otro programa que lanza programas.
- **Proceso**: programa en ejecución, con identidad, memoria y estado propios.
- **Credenciales (UID/GID)**: identidad real y efectiva que el kernel usa para autorizar.
- **`/proc`**: sistema de ficheros virtual que muestra procesos y estado del kernel.

## 3. Caso resuelto

**Datos sintéticos para análisis; no son una captura ni una ejecución real.**

> Caso sintético: un analista ejecuta un comando de listado como su usuario y también con `sudo`, y observa que el segundo muestra archivos que el primero no. Concluye que «el comando cambió».

La conclusión no se sostiene. El **programa** era el mismo; lo que cambió fue la **identidad efectiva** con la que se ejecutó. Con `sudo`, el proceso pasó a tener privilegios que el kernel acepta para leer más archivos. El comando no cambió: cambió quién lo ejecutaba a ojos del kernel.

Razonar así es la diferencia entre describir un síntoma («el comando hace cosas distintas») y localizar una causa («la identidad efectiva es distinta»). El límite de la conclusión: sin comprobar la identidad real y efectiva, no puedes afirmar *por qué* difieren los resultados, solo *que* difieren.

## 4. Práctica individual

Ejecutas el mismo comando de listado como usuario normal y con privilegios, y obtienes resultados distintos. Explica **en qué capa** está la diferencia y **qué dato** registrarías para demostrarlo.

Entrega una respuesta razonada: identifica los datos que utilizas, la decisión y el límite de tu conclusión. Resuelve antes de consultar el solucionario. Esta práctica es de análisis documental; su resolución no acredita haber configurado un host real.

## 5. Evalúa lo aprendido

Responde ambas preguntas y justifica por qué las otras opciones no se sostienen con los datos.

### Pregunta 1

¿Qué hace realmente la shell cuando escribes un comando como `ls`?

- A. Ejecuta el código del kernel directamente
- B. Pide al sistema que arranque un programa, que a su vez pide al kernel el listado
- C. Modifica los permisos del directorio que se va a listar
- D. Cambia tu identidad para poder leer todos los archivos

### Pregunta 2

Dos usuarios obtienen resultados distintos con el mismo comando. ¿Cuál es la explicación más precisa?

- A. El kernel es distinto para cada usuario
- B. El comando cambió de versión entre ejecuciones
- C. La identidad efectiva del proceso es distinta y el kernel autoriza según ella
- D. La shell reordena los argumentos según el usuario

## 6. Aplicación profesional

- SOC: Registrar identidad efectiva y capa de ejecución antes de interpretar un hallazgo como anomalía.
- Red Team autorizado: Distinguir entre una capacidad del programa y un derecho de uso sobre el sistema.
- Evidencia de la etapa: Ficha de host con usuario real, usuario efectivo y comando observado.
- Criterio de dominio: Explica en qué capa ocurre un efecto y con qué identidad antes de concluir.
